# 本地工具型 Agent 设计

日期：2026-10-08

状态：会话中的设计已确认；本文待用户审阅。本文是设计规格，不是实施计划，也不代表产品功能已经实现。

## 1. 目标与已确认决策

将现有 AutoTools 桌面工具箱重构为以 AI 对话为默认入口的本地工具型 Agent。用户用自然语言调用现有能力，Agent 补齐参数、选择工具，执行层返回真实状态和结果。

已确认的范围：

- 保留 Electron 桌面应用，主进程内置 LangChain JS Agent。
- 渲染进程使用 React、Ant Design 和 Ant Design X。
- 对话作为默认首页；视频工具、WebView 调试、闪退监控三个页面保留手动入口。
- 对话和手动入口共享业务服务、执行规则及持续任务状态。
- 模型通过可配置的 OpenAI 兼容 API 接入，配置地址、Key 和模型名称。
- 查询自动执行；文件写入、移动和设备设置变更按操作类型确认。
- 会话和执行记录保存在本地；监控在切换页面后继续运行，退出应用时停止。

首版不包含通用终端、任意脚本执行、自动根因排查、多 Agent、MCP 平台、知识库或云端账户系统。

成功标准：用户可以通过对话完成视频扫描及确认后移动、WebView 调试、启动及停止闪退监控和导出事件；手动页面仍可完成相同操作。所有执行状态由本地服务产生，不能以模型声称执行成功代替工具结果。

## 2. 现有代码与迁移依据

- `src/main/services/fileService.ts` 已包含扫描、移动和文本写入，文件操作使用同步 API。
- `src/main/services/hdcService.ts` 已包含命令执行、流进程、应用及前台应用查询。
- `src/main/services/chromeService.ts` 已包含浏览器检测及启动。
- `src/main/ipc/hdcIpc.ts` 在内存中管理流，事件发给发起窗口；尚无业务任务快照和重连能力。
- `src/renderer/src/pages/HdcDevToolsPage.tsx` 编排探测、修改属性、端口转发和打开端点。
- `src/renderer/src/pages/CrashMonitorPage.tsx` 管理监控状态、日志分行、关键词分类及导出，并在页面卸载时停止流。
- `src/shared/ipc.ts` 和 `src/preload/index.ts` 是现有跨进程类型及通信边界。

迁移期间保护现有未提交的应用名称、窗口标题和监控按钮修改。保留旧页面不要求一次性改写所有 Bootstrap 样式；新界面用 Ant Design，旧样式限制在旧工具页面范围，后续迁移按实际需要进行。

## 3. 架构与模块职责

调用路径：渲染进程 -> preload -> IPC -> Agent 服务 / 手动工具请求 -> 统一执行层 -> 业务服务 -> 本地文件、设备或浏览器。执行事件通过 IPC 回到渲染进程。

建议模块边界：

| 模块 | 责任 | 依赖 |
| --- | --- | --- |
| `main/agent` | 对话上下文、模型适配、LangChain 工具适配、运行取消 | 执行层、配置和记录存储 |
| `main/tools` | 工具定义、参数验证、预览、确认策略、执行和结果裁剪 | 业务服务、任务管理器 |
| `main/tasks` | 监控任务、流生命周期、解析、事件缓冲和快照 | HDC 服务、日志解析 |
| `main/services` | 文件、设备和浏览器领域操作 | Node 与 Electron 系统能力 |
| `main/storage` | 配置、会话和执行记录的本地持久化 | 应用数据目录、系统密钥保护 |
| `shared/agent`、`shared/tools`、`shared/tasks` | IPC 数据契约及公共类型 | 不依赖运行时系统 API |
| `renderer/features/chat` | 会话列表、输入、消息、执行结果、确认交互 | preload API、Ant Design X |
| `renderer/features/settings` | 模型配置、连接测试和脱敏信息 | preload API、Ant Design |
| 现有工具页面 | 手动参数输入、结果和任务详情 | 同一套业务 IPC |

业务服务不依赖 LangChain。工具注册表是唯一的操作及确认策略来源，LangChain 工具是其适配器。渲染进程不接触模型 Key、文件系统或 HDC 命令拼装。

首版不额外运行本地 HTTP 服务器，不要求 LangSmith 或云端 Agent 服务。异步模型请求在主进程执行；文件扫描、复制改为异步操作，避免在主进程持续阻塞界面。

## 4. 工具契约与首版工具集

工具定义包含稳定名称、用途描述、输入 schema、输出 schema、确认策略、预览逻辑和执行函数。所有 IPC 参数在主进程运行时验证，不能仅依赖 TypeScript 类型。

工具结果至少包含状态、结构化数据、用户摘要及错误信息。状态区分成功、部分成功、失败、取消和用户拒绝；结果关联工具调用 ID、运行 ID及可选任务 ID。完整清单保留本地，模型仅接收有大小限制的摘要及可引用的结果 ID。

| 工具 | 主要输入 | 结果 | 确认 |
| --- | --- | --- | --- |
| `video.scan` | 源目录、可选日期区间 | 扫描 ID、视频清单、数量及大小 | 自动 |
| `video.move` | 扫描 ID、选中文件 ID、目标目录 | 每文件实际目标及成功、失败、取消项 | 必须 |
| `device.list` | 无 | 设备 ID 和状态 | 自动 |
| `device.list_apps` | 设备 ID | 应用包名列表 | 自动 |
| `device.foreground_app` | 设备 ID | 前台应用或无法识别 | 自动 |
| `webview.probe` | 设备 ID | 进程、socket、现有转发 | 自动 |
| `webview.enable_debugging` | 设备 ID | 属性修改结果 | 必须 |
| `webview.forward_port` | 设备 ID、本机端口、socket | 转发记录 | 必须 |
| `webview.remove_forward` | 设备 ID、指定转发 | 移除结果 | 必须 |
| `webview.open_endpoint` | 已验证的调试端口、浏览器选择 | 打开结果 | 自动 |
| `crash.start` | 设备 ID、应用包名 | 任务 ID、监控状态 | 自动 |
| `crash.stop` | 本应用任务 ID | 实际停止状态 | 自动 |
| `crash.status` | 任务 ID | 状态、统计及有限事件摘要 | 自动 |
| `crash.export` | 任务 ID、目录、导出范围 | 汇总和事件日志实际路径 | 必须 |

日期筛选延续现有子目录修改时间语义，预览明确展示筛选依据。自然语言日期按本机时区解析，含糊时补充询问。

文件移动使用本地扫描结果中的文件 ID，模型不能提交任意 `Video` 对象来指定未扫描文件。导出正文由本地业务服务生成，不提供通用模型写任意文本工具。现有“raw”日志是捕获事件的原始行，首版不承诺保留全部 hilog 输出。

设备操作始终关联明确设备 ID。只有一台在线设备时可自动选定并展示；多台时先让用户选择。执行前重新验证设备，断连后失败，不自动切换到其他设备。低层 HDC 参数由本地业务服务生成，设备侧命令参数也需限制和验证，不能只依赖本机未启用 shell。

Agent 不注册任意 `hdc.exec`、任意 URL 打开或任意浏览器路径启动工具。调试端点仅生成本机回环地址，浏览器来自本地检测或用户配置并验证的路径。

## 5. 执行确认与状态机

工具调用状态：`requested -> validating -> awaiting_confirmation / executing -> succeeded / partial / failed / cancelled / rejected`。自动执行跳过等待确认；每条调用只产生一个最终结果。

需要确认时，本地生成预览和确认 ID，绑定会话、运行、调用、工具名称、规范化参数、资源快照及预览版本。界面只提交确认 ID 和同意或拒绝，不能通过确认请求重新提交执行参数。批准单次使用，不形成持久授权。

预览展示实际路径、设备 ID、应用、文件数量和影响；用户可以展开完整文件清单。修改文件、目标目录、端口或设备后生成新预览，旧批准失效。资源检查和冲突处理在执行层完成。

文件移动先确定每个目标名称；存在同名文件时预览明确展示改名后的路径。执行时禁止覆盖，源文件身份、大小、修改时间或目标占用改变时重新预览。目标不得与源路径相同；解析实际路径，处理 Windows 路径大小写和链接，避免把文件移到自身后删除源文件。

导出使用唯一名称并禁止覆盖；目录、内容快照或冲突情况变化时重新确认。开始导出时固定事件范围，后续监控事件不改变已经批准的导出内容。

主进程只接受本应用可信窗口及预期 frame 的执行、确认和配置 IPC。模型文本、工具返回文本及日志不能批准调用。手动页面使用相同执行层及确认预览；涉及变更的旧通用 IPC 在迁移完成时移除或限制为内部使用，不能成为绕过策略的旁路。

待确认请求在运行取消、会话删除或应用退出时失效；应用重启不恢复可执行批准。用户拒绝后将拒绝结果交给 Agent，不自动换一个工具执行同一操作。

## 6. Agent 回合与失败处理

单个会话同时只运行一个 Agent 回合。首版全应用最多一个活跃 Agent 回合，其余会话可以查看历史；持续监控任务不占用回合。缺少模型配置时显示设置入口，手动页面仍可使用。

回合顺序：保存用户消息 -> 读取有限上下文 -> 调用模型 -> 验证工具请求 -> 自动执行或等待用户确认 -> 把真实工具结果送回模型 -> 返回回复。参数缺失或多设备歧义时补充询问。

模型输出经适配器转换为产品事件，不把 LangChain 内部事件类型直接作为前端公共契约。首版每回合最多 12 次工具调用；单次模型请求 120 秒、普通设备查询 30 秒超时；用户等待确认和持续监控不计入这两类超时。

停止生成取消模型请求、待确认和后续工具调用。文件移动在当前文件结束后停止后续文件，记录实际完成项；已经完成的动作不承诺回滚。取消不能把已创建的持续任务标成从未执行，界面仍展示任务及停止入口。

同一回合的工具先顺序执行。只读查询遇到可识别的临时失败最多重试一次；移动、导出、设备设置及进程启动不盲目重试。设备操作和相关手动操作按设备串行，文件变更按目标资源协调，避免两个入口并发争用。

错误区分配置错误、连接失败、工具调用能力不足、参数错误、设备断连、资源变化、工具超时和部分执行失败。界面展示恢复操作，记录脱敏诊断。WebView 多步执行在失败处停止，报告已经修改的属性或已经建立的转发，不声称已回滚；清理变更仍遵循确认规则。

文件跨盘移动按复制完成后再删除源文件执行，取消不留下被视为成功的半成品。复制成功但删除失败时报告两处实际路径和重复文件状态，不自动再次移动。

## 7. 持续任务与日志

监控任务状态：`starting -> running -> stopping -> stopped`；启动、运行或停止异常进入 `failed`。停止幂等；同一设备及应用重复启动返回现有运行任务。

任务包含任务 ID、设备、应用、起止时间、状态、统计、事件缓冲、截断计数和退出原因。日志分行、关键词分类和包名提取从页面迁入业务层，保持现有规则；无法可靠提取包名时标记未知，不声称日志属于目标应用。

首版保留每任务最近 500 条匹配事件，每条原始行最多 16 KiB，未完成行缓冲最多 64 KiB；超限标记截断。统计分别展示累计匹配数及当前保留数。导出仅覆盖固定的保留事件快照，并在报告注明已丢弃或截断的内容。日志批量推送，避免逐行更新整段会话。

主进程先注册进程监听，再允许启动成功返回，避免启动早期事件丢失。对话显示任务状态和停止、详情、导出入口；监控页面通过任务 ID 获取相同快照，不维护另一份任务。

切换页面、刷新视图或新建会话不会停止任务。界面订阅时先取快照并按事件序号合并更新。设备断开或进程退出同步真实状态。关闭最后一个窗口退出应用时，取消 Agent、使确认失效并停止本应用拥有的监控子进程；停止等待有界，不能把等待超时报告成已确认停止。

首版不在应用重启后自动启动监控，也不自动删除外部创建的端口转发。历史任务记录保留最终状态；异常退出遗留的运行记录在下次启动标为中断。

## 8. IPC 与界面

命令至少覆盖会话创建、列表和删除、发送消息、取消运行、确认或拒绝、工具预览和执行、任务查询和订阅、模型配置及连接测试。文件夹选择继续使用系统对话框，不用模型推测用户路径。

事件统一携带序号、时间及相关会话、运行、调用或任务 ID。事件包括文本增量、工具请求、确认等待、执行状态、工具结果、任务更新和回合结束。窗口只收到其订阅数据；取消订阅释放监听，不停止业务任务。

渲染进程通过独立 IPC 适配层维护产品消息状态，再映射到 Ant Design X。组件库只承担展示；Agent 循环、确认授权、持久化和工具执行都在主进程。具体库 API 与版本在实施阶段按当前文档验证。

默认首页有会话列表、消息区和输入区，导航同时保留三个工具页面和设置。消息支持文本、结构化结果和执行状态，工具详情可折叠。确认组件支持展开完整参数，等待期间明确显示尚未执行。

文件结果使用表格；设备和应用使用选择组件；监控显示任务状态及详情链接。停止生成和停止监控是不同控件。消息渲染禁用原始 HTML，对链接进行校验；不能将模型生成的按钮或文本解释为执行授权。

## 9. 配置、存储与模型数据

非敏感配置和会话采用带 schema 版本的本地 JSON，存放于应用用户数据目录；使用串行写入、临时文件和原子替换。增量文本在内存累积，定期及结束时保存，不逐 token 写盘。加载失败保留损坏文件副本并报告，不静默丢弃记录。

Key 单独通过系统保护能力保存；不进入会话、执行日志或普通 JSON，不回传完整 Key。系统保护不可用时只保存在本次进程内存中，界面明确提示重启需重新填写。发送到自定义地址前明确展示配置的服务地址。

连接测试分别报告普通对话、流式响应和工具调用是否可用。测试工具为本地无副作用工具，不能操作真实文件或设备。仅接受预期工具 schema；服务不支持工具调用时对话可用、工具模式禁用，并展示原因。

模型上下文只发送当前会话最近 20 个完整回合、每条工具摘要最多 8 KiB，总输入文本预算 64 KiB；保持工具请求与结果配对。当前用户消息超限提示缩短，不静默裁掉指令。单回合结果超限时裁剪数据并标注，不继续无限扩大上下文。

云端服务会收到对话和必要的工具摘要，设置页说明这一数据流。完整本地文件列表和连续设备日志不会默认全量上传。凭据从错误信息中脱敏。工具描述和系统提示要求把日志、文件名和工具正文当作数据，本地策略始终独立执行。

删除会话清除对应本地消息和执行记录，不自动停止已运行的任务；任务仍可从监控页面访问，也不删除已导出的文件。首版不包含历史监控日志跨重启恢复，持久化任务元信息和有限的最终摘要。

## 10. 实施顺序与验收

本文只确定阶段和验收边界，具体提交、文件拆分和测试命令在后续实施计划中编写。

### 阶段一：共享业务服务及任务管理

提取 WebView 编排、监控解析及导出，补充设备目标、异步文件操作、执行预览和确认策略。旧页面切换至共享 IPC，保留已有功能和本次会话之前的本地修改。

验收：切换页面不停止监控；对话未来需要的任务快照已有稳定接口；移动预览对应真实目标；旧入口不能绕过变更确认。

### 阶段二：模型设置及只读对话

建立模型配置、连接测试、本地会话、Agent 服务、事件适配及 Ant Design X 默认首页。接入扫描、设备查询、应用查询和 WebView 探测。

验收：配置可保存且 Key 不泄漏；流式回复可取消；多设备会补充询问；前端显示真实工具结果；查询失败不被解释为成功。

### 阶段三：变更工具及持续任务

接入确认、视频移动、调试设置和转发、监控启动及停止、事件导出；对话和手动页面操作相同任务。执行界面检查和打包验证。

验收：扫描后确认移动；调试中途失败呈现已完成步骤；对话启动监控后手动页面能停止；重启恢复会话但不自动执行待确认操作。

### 必须覆盖的验证

- 预览参数不可替换、批准只能使用一次、失效或其他调用的确认不能执行。
- 源文件变化、同名目标竞争、源目标相同、复制后删除失败及取消的真实结果。
- 多设备选择、设备断开、重复监控、跨页状态、日志分块及截断、子进程关闭。
- 模型工具参数无效、服务无工具调用能力、网络超时、取消和工具次数上限。
- IPC 来路及参数验证、Key 脱敏、会话持久化、重启时运行状态修复。
- 桌面及窄窗口下消息、长路径、确认清单、旧页面样式和按钮布局。
- TypeScript、lint、构建及打包资源路径检查；自动化使用假模型和假 HDC，真实 API 和设备验证单独记录结果，不把模拟通过等同于真实兼容。

## 11. 风险与设计取舍

OpenAI 兼容服务之间的工具调用和流式行为存在差异，首版以能力测试结果为准，不承诺任意服务兼容。现有监控关键词和包名提取仅是启发式事件捕获，不能等同于根因诊断。

主进程内置 Agent 简化部署，也让耗时或同步工作影响应用；首版采用异步 IO 和有界缓冲，独立进程隔离作为实测需要后再考虑的演进。

保留旧页面降低迁移风险，但必须把状态及变更操作迁到统一业务边界；仅新增聊天页面而保留两套业务实现不满足本规格。
